# 금융기관·변호사 조회처 추출 자동화

분개장의 **거래처 열**에서 금융·법률 키워드와 기관명·별칭을 검색해 조회처 이름을 뽑고,
기관별로 중복을 제거해 **Control Sheet를 만들어 준다.**

**Control Sheet는 입력이 아니라 출력이다.** 고르는 것은 분개장 하나뿐이고,
프로그램이 빈 표준 양식을 복사해 `정보입력&출력&Control sheet` 시트 **A59부터** 한 행씩 채운다.
A열(조회처명)·C열(온라인 표시)·H열(YES)만 채우고 나머지 목록 열은 공란으로 둔다.

주소 조사·담당자 확인·발송 판단·조회서 출력은 **하지 않는다.**

---

## 1. 설치

```
pip install -r requirements.txt
```

필요한 것은 Python 3.10 이상, `openpyxl`, `pywin32`, 그리고 **Microsoft Excel(데스크톱)** 이다.
Excel은 XLSM의 VBA·ActiveX·도형을 보존한 채 저장하기 위해 반드시 필요하다
(이 템플릿은 openpyxl로는 읽기조차 실패한다 — 아래 6장 참조).

## 2. 실행

### 화면으로 실행

`실행.bat` 더블클릭 (또는 `python src/app.py`)

```
1) 분개장 고르기  →  실행  →  만들어진 Control Sheet 열기
```

- 저장 위치는 **분개장 옆 `output` 폴더**로 자동으로 정해진다. 바꾸고 싶으면 직접 고르면 된다.
- 만들어지는 파일 이름: `Control Sheet_<분개장이름>_<날짜시각>.xlsm`.
  **덮어쓰지 않는다.** 실행할 때마다 새 파일이 생긴다.
- `저장하지 않고 검색만` 을 켜면 파일을 만들지 않고 찾은 목록만 본다.
- 조회처 목록과 검증 결과는 화면 아래 `진행 기록`에 그대로 나온다.
- **진행 기록**에는 읽은 분개장 정보, 찾은 조회처, A열에서 뺀 근거, 만든 파일 경로,
  검증 14항목이 줄줄이 남는다(한 번 실행에 약 55줄). 실행 전에는 무엇이 나올지 적혀 있다.
- **화면 맨 아래 상태 표시줄**에 진행률·현재 단계·경과 시간이 보인다.
  진행률은 **끝난 단계 기준**이다. 시간으로 추정하지 않는다
  (회계감사 자동화 프로그램의 `SegmentProgress`를 옮겨 왔다).

### 어떤 양식을 쓰는가

찾는 순서는 이렇다.

| 순서 | 위치 | 쓰임 |
|---|---|---|
| 1 | `--template`로 지정한 파일 | 한 번만 다른 양식을 쓸 때 |
| 2 | 실행 파일 옆 `template/` 폴더의 .xlsm | **자기 양식을 쓰려면 여기 넣는다** |
| 3 | 프로그램에 함께 들어 있는 `Control Sheet_표준양식.xlsm` | 기본값 |

기본 양식은 실제로 쓰던 Control Sheet에서 **개인·회사 정보를 지운 빈 양식**이다
(`tools/make_template.py`가 만든다). 시트 16개·수식·매크로·ActiveX·조회서 양식은 그대로 있고,
회계법인명·담당 회계사·연락처·감사대상법인 정보·이전 조회처 목록·주소록 출력물은 비어 있다.

### exe로 만들기

`빌드.bat` 더블클릭. `dist\조회처추출.exe`(약 19MB)와 `dist\config`가 만들어진다.
**dist 폴더를 통째로** 건네면 Python 없이 실행된다.

- 설정은 exe 옆 `config`를 먼저 읽는다. 기관 사전을 고칠 때 exe를 다시 만들지 않아도 된다.
  exe 옆에 `config`가 없으면 exe 안에 넣어 둔 사본을 쓴다.
- exe는 **화면 전용**이다(`console=False`). 명령줄로 쓸 때는 `python src/app.py`를 쓴다.
- 받는 PC에도 **Microsoft Excel(데스크톱)** 이 있어야 저장 단계가 돈다.

### 시험하기 (실제 감사 자료 없이)

`E2E테스트.bat` 더블클릭. 세 가지를 차례로 한다.

| 단계 | 하는 일 | 결과 |
|---|---|---|
| 1 | `tools/make_samples.py` — 견본 분개장 2개 생성(양식이 서로 다르다) | `samples/` |
| 2 | `tests/verify.py` — 요구사항 테스트 46건 | **통과 46 / 실패 0 / 미검증 0** |
| 3 | `src/app.py` — 양식을 복사해 Control Sheet를 만든다 | `samples/output/`에 새 파일, 조회처 19건, 저장 검증 통과 12 / 실패 0 / 미검증 2 |

견본 거래처는 지어낸 이름이거나 공개된 금융기관명이다. 실제 감사 자료는 쓰지 않는다.
끝나면 `samples/output/`에 생긴 파일을 직접 열어 A59부터 19건, H열 `YES`, C열 온라인 표시,
맨 뒤 `자동화_제외후보` 시트의 4대보험 3건·PG 2건을 눈으로 확인하면 된다.
**양식 원본(`template/`)은 그대로여야 한다.**

실제 분개장·Control Sheet로 같은 테스트를 돌리려면 경로를 인자로 준다.

```
python tests/verify.py "<분개장.xlsx>" "<ControlSheet.xlsm>"
```

### 폴더 구조

```
src/core/     검색·통합·저장 (화면과 무관)
src/ui/       실행 화면 — theme(색·글자) / widgets(둥근 카드·알약 단추·진행막대) / window(배치·상태표시줄)
config/       기관 사전·키워드·입력 양식  ← exe 옆에 두면 이쪽을 먼저 읽는다
template/     빈 Control Sheet 양식        ← 자기 양식을 넣으면 그걸 쓴다
tests/        요구사항 테스트 44건
tools/        견본 생성·사전 병합·분개장 분석
samples/      견본 파일 (E2E테스트.bat이 만든다)
dist/         빌드 결과 (exe + config)
```

### 명령줄로 실행

```
python src/app.py --journal "<분개장.xlsx>"
```

이것만으로 `<분개장 폴더>\output\Control Sheet_<분개장이름>_<날짜시각>.xlsm`이 만들어진다.

| 옵션 | 뜻 | 기본값 |
|---|---|---|
| `--journal` | 분개장 파일 | (필수) |
| `--target` | **이미 있는** Control Sheet에 쓸 때만 지정 | 없음(새로 만든다) |
| `--outdir` | 출력 폴더 | 분개장 옆 `output/` |
| `--template` | 쓸 양식(.xlsm) | `template/` 폴더 또는 내장 표준양식 |
| `--sheet` | 출력 시트 이름 | `정보입력&출력&Control sheet` |
| `--profile` | 입력 양식 프로파일 | 자동 선택 |
| `--start-row` | 출력 시작 행 | `59` |
| `--dry-run` | 저장 없이 검색만 | 꺼짐 |

종료 코드: `0` 성공 / `2` 입력(분개장) 오류 / `3` 저장 실패 / `4` 양식 오류 / `1` 그 밖의 오류.
**입력 오류와 "검색 0건"은 서로 다른 결과로 처리한다.** 읽기 실패는 0건으로 바꾸지 않는다.

## 3. 무엇이 어디에 써지는가

프로그램이 덧붙이는 `자동화_` 시트 4개는 **통합문서 맨 뒤**에 이 순서로 온다 —
`자동화_기관상세` → `자동화_제외후보` → `자동화_검색근거` → `자동화_실행기록`.
조서를 열었을 때 원래 시트가 먼저 보이게 하기 위해서다.

`정보입력&출력&Control sheet`

| 열 | 내용 |
|---|---|
| A | 조회처명 — A59부터 결과 개수만큼. N번째는 A(58+N) |
| B | 공란 (주소) |
| **C** | **금융결제원 온라인 발급 가능 기관이면 `온라인`, 아니면 공란** |
| D~G | 공란 (담당자·전화·우편번호·조회처분류) |
| H | `YES` |
| I~L | 공란 (NO.·Ref·발송일·회수여부) |

58행 제목, 상단 기본정보(1~56행), 다른 양식 시트는 건드리지 않는다.
주소·연락처·조회처분류·순번·Ref는 **알 수 있어도 넣지 않는다.**
C열만 예외로 온라인 발급 여부를 표시한다(아래 4장).

보조 시트 3개가 매 실행마다 새로 만들어진다(이전 실행분은 지우고 다시 씀).

| 시트 | 내용 |
|---|---|
| `자동화_기관상세` | 후보ID, 조회처명, **이름 추출 방식**, 사전 분류, 원문 명칭 목록, 지점·계좌 단서, 관련 계정과목, 검색 키워드, 거래기간·건수, 이름을 얻은 근거 |
| `자동화_검색근거` | 일치한 원본 행 전건. `직접일치` / `전표문맥` / `이름미확인` / `제외` 구분, 원본 시트·행·전표번호, **적요 미채택 조각** |
| `자동화_제외후보` | **A열에 넣지 않은 후보**(C등급 일반 거래처). 등급 판정 근거·일치 키워드·건수를 함께 남긴다. 버리지 않고 여기 보존한다. `검토 필요` 항목이 맨 위 |
| `자동화_실행기록` | 입력 파일·기간·사전 버전·처리 건수·등급별 건수·백업 위치·자동 작성 범위 |

계좌 단서는 텍스트 서식으로 기록해 **선행 0을 유지**한다(`00040`, `04-013`).
확인되지 않은 숫자를 계좌번호라고 단정하지 않으므로 열 제목도 "계좌 단서"다.

## 4. 검색 기준과 이름 추출·통합 규칙

### 검색 대상은 '거래처' 열 하나뿐이다

**거래처명 자체에** 지정 키워드 또는 기관 사전의 기관명·별칭이 들어 있어야 후보가 된다.
적요나 계정과목에 키워드가 있다는 이유로 그 행의 거래처를 포함하지 않는다.

| 거래처 | 적요 | 계정과목 | 결과 |
|---|---|---|---|
| 일반상사 | 국민은행 송금 | 외상매입금 | **제외** |
| 일반상사 | 월세 | 지급임차료 | **제외** |
| 마나마나(주) | 렌탈료 | 지급임차료 | **제외** (거래처명에 키워드·사전 일치 없음) |
| (공란) | 국민은행 대출이자 | 이자비용 | **제외** |
| 가나다렌탈 | 사무용품 | 소모품비 | **포함** (`렌탈`) |
| 하나은행(00000) | 대체 | 보통예금 | **포함** (`은행`·사전) |
| 법무법인 가나다 | 등기 | 지급수수료 | **포함** (`법무`) |
| 농협(000000) | 대체 | 보통예금 | **포함** (사전 별칭 `농협`) |
| 건강보험 | 4대보험 | 예수금 | **포함** (`보험`) |

`건강보험`처럼 거래처명 자체에 지정 키워드가 있으면 포함한다.
**금융기관인지 판단해 임의로 빼는 필터는 두지 않는다.**

적요·계정과목 원문은 `자동화_검색근거` 시트에 **근거로만** 남는다.

### 검색 조건

- 금융 키워드 32개: 은행·보험·해상·화재·이자·금융·보증·부보·저당·질권·차입·대출·예금·적금·
  사용제한·대여·상환·캐피탈·투자·증권·배당·계좌·신용장·파생·어음·수표·견질·신용·당좌·리스·임차·렌탈
- 법률 키워드 8개: 법무·법률·변호사·김앤장·소송·배상·성공보수·로펌
- 정규식: `L/C` (`L / C`, `L.C.` 포함, 영문 단어 속 `LC`는 제외)
- 기관 사전(`institutions.csv`)의 기관명·별칭

`고문료`·`자문료`·`파이낸셜` 같은 보완 키워드는 **기본 검색에 자동 적용하지 않는다.**
`supplementary_keywords_examples`에 참고용으로만 두었다.

> **용어**: 아래 분류는 **이름을 어떻게 얻었는지**를 말한다. 사전에 있다는 것은 *그 사전 항목에
> 등재돼 있다*는 사실일 뿐이고, 접미사·명칭패턴에 맞았다는 것은 *그런 형태의 문자열이었다*는
> 뜻이다. **어느 것도 실제 금융기관·변호사라는 확정이나 발송 대상 판정이 아니다.**

### 포함된 거래처명에서 이름을 얻는 순서

1. `institutions.csv` 별칭 (긴 별칭 우선) → `하나은행(00000)`, `(주)하나은행`, `KEB하나은행` = `하나은행` 한 행.
2. 법률기관 명칭패턴(이름이 뒤에 오는 형태) → `법무법인 좋은생각`.
3. 접미사 규칙 → `SBI저축은행`, `산은캐피탈`, `제이앤법무사사무소`.
4. 접미사·패턴으로 뽑은 이름이 사전 별칭과 완전히 같으면 사전 기관으로 합친다(`농협대출(2270-03)` → `농협`).
5. **1~4로 이름을 못 얻으면 검색에 일치한 원문 거래처 이름을 그대로 쓴다.**
   사전 미등록이라는 이유로 제외하지 않는다.

**거래처명이 검색 조건에 맞지 않으면 적요·계정과목·전표 문맥으로 구제하지 않는다.**
적요에서 별도 기관을 뽑지 않고, 같은 전표의 다른 행에서 후보를 추가하거나 연결하지도 않는다.
(`extract_modes.description = []`, `use_voucher_context = false`)

### 등급(layer) — A열에 무엇을 쓸지

검색된 거래처를 3등급으로 나눈다. **A·B등급만 Control Sheet A열에 쓰고, C등급은
`자동화_제외후보` 시트에만 남긴다.** 등급은 "이름을 어떻게 얻었는가"가 아니라
**"거래처명이 금융·법률 기관 명칭 형태인가"** 로 판정한다.

| 등급 | 조건 | 예 | A열 |
|---|---|---|---|
| **A** | 기관 사전(`institutions.csv`)의 기관명·별칭과 일치 | `하나은행`, `IBK기업은행`, `KG이니시스`, `농협` | ✅ |
| **B** | 사전에 없지만 거래처명에 `layer_b_terms`의 금융·법률 낱말이 있음 | `한한손해보험`, `호텔캐피탈`, `법무법인 가나다`, `마바사 법무사사무소` | ✅ |
| **C** | 그 밖 — 일반 거래처 | `행복마트 포스보증금/구미`, `건강보험`, `두리두리상사` | ❌ |

**`exclude_categories`에 적은 분류는 A등급 조건을 만족해도 C로 내린다.**
기본값은 `["전자금융", "사회보험"]` 두 가지다.

| 분류 | 무엇 | 왜 뺐나 |
|---|---|---|
| `전자금융` 17건 | PG·간편결제사 | 카드매출 정산처라 금융거래 조회 대상이 아니라는 판단 |
| `사회보험` 3건 | 국민건강보험공단·국민연금공단·근로복지공단 | 4대보험(국민연금·건강·고용·산재)과 장기요양보험은 예수금 납부처일 뿐 조회 대상이 아니다 |

둘 다 **삭제가 아니라 제외후보 시트로 보낸다.** 판정 근거(`제외 분류 '사회보험' — …`)가 함께 남고,
되살리려면 `keywords.json`의 `exclude_categories`에서 분류를 지우면 된다.
카드사(`카드`)와 민간 보험사(`보험` — 삼성생명보험·IBK연금보험 등)는 조회 대상이므로 넣지 않았다.

**사회보험 기관의 별칭은 고유 명칭만 둔다.** `고용보험`·`건강보험` 같은 일반 명사를 별칭에 넣으면
`한국고용보험사무소` 같은 **다른 거래처를 공단으로 잘못 통합한다**(테스트 17·20g가 이것을 잡는다).
`건강보험`·`산재보험료`처럼 짧게 적힌 거래처는 사전에 걸리지 않지만 C등급이라 어차피 A열에 나오지 않는다.

**B등급이 있는 이유**는 사전에 아직 없는 기관을 놓치지 않기 위해서다.
DB 정확 일치만 통과시키면 신설·소규모 금융기관과 법무사사무소가 조용히 사라진다.
감사에서 조회처 누락은 일반 거래처가 섞이는 것보다 위험하다.

`layer_b_terms`에 **`보험`·`보증`·`리스`·`신용`·`투자` 단독은 넣지 않았다.**
넣으면 `홈플러스 포스보증금`, `아이리스`, `2008.10.20신용상사` 같은 일반 거래처가 전부 올라온다.

C등급 중 `layer_c_review_terms`(대출·차입·자금·투자·펀드·금융·결제원 등)가 걸린 것은
**`검토 필요`** 로 표시해 제외후보 시트 맨 위에 모은다.
예: `기업시설자금대출(00033)`은 IBK기업은행 여신계좌명으로 보이지만 거래처명에 은행명이 없다.

`output_layers`를 `["A"]`로 바꾸면 사전 일치만 출력한다. 기본값은 `["A","B"]`다.

### 중복 제거와 정렬

- 통합 키는 사전 기관은 `institution_id`, 원문 후보는 **공백 제거·대문자화한 원문 이름**이다.
- **같은 금융그룹이라도 다른 법인은 합치지 않는다.** 신한은행 ≠ 신한카드, 기업은행 ≠ 기업비씨.
- 지점·계좌가 달라도 같은 기관이면 목록은 한 행, 단서는 거래처 원문에서 뽑아
  `자동화_기관상세`에 모은다(선행 0 유지).
- 원문 후보는 서로 다른 이름이면 따로 남긴다. 유사한 이름이나 오타를 추측으로 합치지 않는다.
- 순서는 원본에서 처음 나온 순서다. 같은 입력·같은 사전이면 결과와 순서가 같다.
- **모든 출력 후보는 적어도 하나의 '거래처 열 직접 일치' 근거를 가진다.**
  어떤 키워드 또는 기관 별칭으로 포함됐는지는 근거 시트의 `검색 키워드` 열에 남는다
  (사전 별칭은 `사전:농협` 형태).

#### 제외 이름 일치 규칙

- 공백을 지우고 대문자로 바꾼 뒤 **완전히 같을 때만** 제외한다.
  끝부분이 같다는 이유로 제외하지 않는다 — `고용보험`을 넣어도 `한국고용보험사무소`는 남는다.
- 비교 대상은 **조회처명 · 기관ID(`institution_id`) · 실제로 맞은 별칭** 세 가지다.
  `기업비씨`, `bank_hana`, `KEB하나은행` 중 아무것이나 써도 된다.
- **사전 등록 기관과 미등록 원문 거래처에 똑같이 적용된다.**
- 제외된 항목은 `자동화_검색근거` 시트에 `제외` 구분으로 남고, 비고에 원문과 적용 규칙이 적힌다.
- 한 행에서 뽑힌 이름이 전부 제외되면 그 행은 `전부제외`로 분류되며, 전표문맥으로 되살아나지 않는다.

기본값이 비어 있는 이유: 개발자 판단으로 거래처를 지우지 않기 위해서다.
`건강보험`처럼 조회처가 아닌 것도 후보 자체는 만들되 C등급으로 제외후보 시트에 남긴다.

## 6. 수치 읽는 법 — 원본 행 수 vs 근거 연결 건수

두 가지는 **다른 단위이고 서로 더하지 않는다.** 실행기록·화면·문서에서 `[행]`, `[연결]` 접두어로 구분한다.

| 단위 | 항목 | 뜻 |
|---|---|---|
| `[행]` | 검색된 원본 행 수 | 키워드가 맞은 분개장 행의 개수(중복 없음) |
| `[행]` | 후보 직접연결 / 전표문맥 / 이름미확인 / 전부제외 | 각 행이 **딱 하나**로 분류된다. 넷의 합 = 검색된 원본 행 수 |
| `[행]` | 근거에 연결된 고유 행 수 | 근거 시트에 나타난 서로 다른 (시트, 행) 개수. 검색된 원본 행 수와 같아야 한다 |
| `[연결]` | 직접일치 / 전표문맥 / 이름미확인 / 제외 근거 레코드 | `자동화_검색근거` 시트의 줄 수. 한 행이 여러 후보에 연결되면 여러 줄이 된다 |
| `[연결]` | 근거 레코드 합계 | 근거 시트의 전체 줄 수 |

그래서 연결 건수는 항상 행 수 이상이다. 예: 적요에 은행이 둘 있는 행 1개 → `[행] 직접연결 1`,
`[연결] 직접일치 2`.

## 7. 저장 방식과 안전장치

`openpyxl`은 이 템플릿을 **읽지 못한다**
(`ValueError: Unable to read workbook … Max value is 14` — sharedStrings의 font family 값이
openpyxl 허용 범위를 넘는다). 그래서 저장은 전부 **Windows Excel COM**으로 한다.
`keep_vba=True`로 해결되는 문제가 아니다.

저장 절차:

1. 대상 파일 잠금 확인(`~$` 잠금 파일 + 쓰기 열기 시도). 잠겨 있으면 **중단**한다.
   사용자의 Excel을 강제로 닫지 않는다.
2. `backup/` 폴더에 타임스탬프 백업을 만든다.
3. 같은 폴더의 **임시본**을 열고, 쓰기 전에 기존 상태를 수집한다
   (모든 시트의 수식 주소·내용, 도형 이름·종류, ActiveX 이름·progID, VBA 구성요소 이름·종류·코드 본문).
   매크로 자동실행 차단(`AutomationSecurity=ForceDisable`, `EnableEvents=False`),
   외부 링크 갱신 차단(`UpdateLinks=0`, `AskToUpdateLinks=False`).
   조회서 출력 매크로와 인쇄는 실행하지 않는다.
4. 기존 목록 범위(A59:L끝, 이전 실행기록의 끝행 포함)를 지우고 이번 결과만 쓴다.
   59행 서식을 복사해 확장하고 H열에 YES/NO 유효성 검사를 다시 건다.
5. 임시본을 저장하고 **다시 열어** 같은 항목을 수집해 대조한다.
6. **FAIL이 하나도 없어야** 대상 파일을 교체한다. 실패하면 원본을 그대로 두고 임시본 경로를 알려준다.

### 검증 항목과 3단계 상태

결과는 `PASS` / `FAIL` / `UNVERIFIED`로 나온다. **검사하지 못한 것은 PASS로 올리지 않는다.**

| 항목 | 방법 |
|---|---|
| A열 연속 작성 / H열 YES / B:G·I:L 공란 / 잔여행 없음 / A열 중복 없음 | 저장본에서 셀을 직접 읽어 대조 |
| 기존 시트 보존 | 시트 이름 목록 비교. 추가는 자동화 보조 시트 4개만 허용 |
| 기존 수식 보존 | **시트명 + 셀 주소 + 수식 문자열**을 전수 대조. 개수 비교가 아니다 |
| 수식 목록 조회 실패 | `SpecialCells`는 *수식이 없을 때*도 *조회에 실패할 때*도 COM 예외를 던진다. `UsedRange.HasFormula`라는 **독립 경로**로 교차 확인해, `False`(수식 없음)로 확인될 때만 정상 처리한다. 확인되지 않으면 사유와 함께 **UNVERIFIED** |
| 부분 수집 | 셀 수와 실제 수집 개수가 다르면 **UNVERIFIED**. 빈 집합으로 비교해 PASS로 만들지 않는다 |
| VBA 구성요소 보존 | **이름 + 종류 + 코드 본문 전문**을 대조. 새 보조 시트의 빈 코드모듈 추가는 구별해서 표시 |
| 도형 / ActiveX | 이름·종류·progID 목록 대조 |
| 도형·ActiveX 내부 속성·바이너리 | **UNVERIFIED** — 컨트롤 속성값·이미지 데이터·이벤트 바인딩은 비교하지 않음 |
| 매크로 동작 | **UNVERIFIED** — 기존 매크로를 실행하지 않음 |
| VBA 접근이 차단된 환경 | **UNVERIFIED** — PASS로 처리하지 않음 |
| 수식이 한 시트에 5,000개를 넘는 경우 | 그 시트는 **UNVERIFIED**로 기록하고 대조에서 뺀다 |

허용된 변경 범위는 **조회처 출력 영역(`정보입력&출력&Control sheet`의 A59:L{정리한 끝행})과
자동화 보조 시트 3개**뿐이다. 그 밖의 수식이 사라지거나 바뀌면 FAIL이며 저장하지 않는다.

### Excel 연결이 끊길 때

`RPC 서버를 사용할 수 없습니다` / `원격 프로시저를 호출하지 못했습니다`는
**Excel 프로세스와의 통신이 끊겼다**는 뜻이다. 파일이 깨진 것이 아니고 원본도 그대로다.
Excel을 여러 번 띄웠다 닫으면 생기며, 한 번 끊기면 Excel이 백그라운드에 남아
임시본을 붙잡고 **다음 실행까지 막는다.**

프로그램이 이렇게 대응한다.

| 대응 | 내용 |
|---|---|
| 자동 재시도 | 저장 단계를 최대 3회(5초 간격). **오류 코드(HRESULT)로 연결 끊김만** 골라 재시도한다. 검증 실패는 재시도하지 않는다 |
| 좀비 Excel 정리 | 자기가 띄운 Excel의 프로세스 번호를 기억해 두었다가, 정상 종료가 안 되면 **그 번호만** 끝낸다. 사용자가 열어 둔 Excel은 건드리지 않는다 |
| 잔재 정리 | 실행 시작에 이전 임시본(`~자동화임시_*`)을 지우고, 저장 실패 시 만들다 만 출력 파일을 지운다 |
| 안내 | 3회 모두 실패하면 "Excel 창을 모두 닫고 작업 관리자에서 남은 Excel을 끝낸 뒤 다시 실행하라"고 알린다 |

테스트(`tests/verify.py`)도 같은 원칙이다. 연결 끊김으로 실패한 케이스만 한 번 다시 돌리고,
**요구사항 위반(AssertionError)은 절대 다시 돌리지 않는다.**

## 8. 확인된 한계

### 검색·출력 범위
- **거래처명에 키워드·사전 일치가 없으면 빠진다.** 적요에만 은행명이 있거나 거래처가
  공란인 거래는 결과에 나오지 않는다. 이번 검색 기준이 그렇게 정해져 있다.
- **C등급은 A열에 나오지 않는다.** 지워지지는 않고 `자동화_제외후보` 시트에 남는다.
  실제 금융거래인데 거래처명이 일반적이면(`기업시설자금대출(00033)`) C등급으로 떨어진다.
  그래서 `검토 필요` 표시를 두었으니 제외후보 시트 위쪽을 반드시 확인하라.

### 기관 사전(524건)에서 확인하지 못한 것
- **등기 상호를 전수 대조하지 않았다.** `display_name`은 협회 표기 또는 실무 통용 상호다.
  조회서 수신인 상호가 중요하면 등기부·DART로 확인해야 한다.
- **외국은행 국내지점 35건은 단일 출처(위키백과)**이고 은행연합회 원본 확인에 실패했다.
  특히 **크레디트스위스은행 서울지점의 존속 여부와 UBS 서울지점 누락 여부**를 확인하지 못했다.
- **외국계 재보험 한국지점 9곳은 등기상호 미검증이라 일부러 넣지 않았다**(스코르·스위스리·
  퍼시픽라이프리·스타인터내셔널·AGCS·FM Global 등). 필요하면 확인 후 추가하라.
- **지역신용보증재단 4건**(경기·강원·경북·경남)의 정식명칭은 검색 요약에서 나온 것으로 미검증이다.
- **저축은행 옛 사명 일부 누락**: 페퍼(구 늘푸른), OSB, 키움예스(구 예스), OK(구 예주·예나래) 등의
  옛 이름을 별칭에 넣지 않았다. **과거 3~5년치 분개장을 돌리면 이 건들이 안 잡힌다.**
- **전자금융업자 17건·대부 5건은 금감원 등록명부 대조를 못 했다.** 업계 통용 표기다.
  `아프로파이낸셜대부`는 2023년 10월 대부업 등록을 반납해 현재 대부업자가 아니다.
- **자산운용 254개사, 신기술금융 99개사가 빠져 있다.** 협회 등재 전수 중 선별했다.
  다만 이름이 `…자산운용`·`…투자운용`으로 끝나면 B등급으로 잡히므로 누락 위험은 낮다.
- **`대화은행`(싱가포르 UOB 서울지점)의 상호를 확인하지 못했다.**

### 그 밖
- **이름을 얻은 방식도, 등급도 기관 확정이 아니다.** 사전 등재·낱말 일치는 문자열의 형태일 뿐이며,
  실제 금융기관·변호사인지, 조회서를 보낼 대상인지는 이 프로그램이 판정하지 않는다.
- **오타로 보이는 이름도 고치지 않는다.** `한한손해보험`은 그대로 남는다.
- `.xls`, `.csv` 분개장은 지원하지 않는다. `.xlsx` / `.xlsm`만 읽는다.
- Excel이 설치되지 않은 PC에서는 저장 단계가 동작하지 않는다(검색·`--dry-run`은 가능).
- **도형·ActiveX의 내부 속성과 바이너리 내용, 매크로의 실제 동작은 검증하지 않았다**(UNVERIFIED).
- **다른 회계프로그램 양식은 검증하지 못했다.** 실제 파일이 없다.
- **실제 분개장으로는 검증하지 않았다.** 분개장 쪽은 합성 견본으로만 확인했다.
  실제 분개장으로는 `python tests/verify.py "<분개장>"` 을 직접 돌려 봐야 한다.
  Control Sheet 쪽은 실제 양식(시트 16개·수식 770개·VBA 19개·도형 10개·ActiveX 4개)으로
  저장·보존 검증을 통과했다.
- **기본 양식은 쓰던 조서에서 정보를 지운 것이다.** 지운 자리(회계법인명·담당자·감사대상법인)는
  사람이 채워야 한다. 프로그램은 조회처 목록만 채운다.
- exe는 **읽기→검색→양식 복사→저장→검증 12항목까지** 실제로 돌려 확인했다
  (`조회처추출.exe --journal <분개장> --outdir <폴더>`, 종료코드 0, 조회처 19건).
  화면에서 마우스로 고르고 누르는 부분만 사람이 확인하면 된다.
- **사회보험 기관은 3곳만 넣었다.** 4대보험 징수기관 외에 건강보험심사평가원 등은 넣지 않았다.
- 고해상도(200% 배율) 화면에서는 Windows가 창을 확대한다. 글자가 다소 흐릴 수 있다.
